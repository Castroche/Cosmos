# 2026-10-10 自动交易决策与平仓恢复修复

本轮验收标准是自动交易链的持续工作和异常恢复，不能以进程存活或健康接口成功替代。用户要求保持自动交易停止，只更新修复；不重新启用 OKX Demo 自动下单。

## 已确认的故障

- ETH 在北京时间 01:27、01:33 连续发生决策合约错误，分别为缺少持仓 ID/版本和持仓目标不匹配。实际传给 LLM 的 `symbol_positions` 没有持仓 ID/版本，虽然提示和校验要求必须返回这些字段。
- 对账会增加持仓版本。原管理接口在 LLM 返回后要求版本仍完全相同，即使变化只涉及报价极值和观察时间，也可能拒绝管理决策。
- 有限重试再次失败后取消 Thesis，却没有留下后续等待。已有持仓和 TRIGGERED 计划阻止无活动任务分支再次决策，形成持续降级。
- SOL 在 20:14 前后平仓保护清理发生异常，之后出现本地数量 31.46、交易所数量 0 的待确认记录。平仓订单的确认没有在保护清理异常路径中保存；已有的成交归属逻辑只认本地已知订单 ID，导致记录长期停留在 OPEN。

## 修改

1. LLM 上下文补充来自本地受管理持仓的 ID、版本、状态、计划 ID，并统一合约符号和方向；账户数量、权益、杠杆仍由确定性风控处理。
2. 管理决策必须引用实际提供的持仓快照。只有版本、观察时间和报价极值变化时才能重新绑定当前记录；数量、均价、止损、目标进度、管理版本、持仓归属或退出请求变化均拒绝旧决策。应用管理前在账户串行锁内再次检查。
3. 失败后持续保留有间隔的恢复唤醒；检测已有持仓缺少等待/队列的情况并补充后续评估。无效决策不会取消仍归属持仓的 Thesis。成功管理没有提供等待规则时保留 30 分钟后的评估。普通行情更新不会绕过该间隔。
4. 保护清理失败时保留异常携带的平仓订单确认。旧记录可以通过真实成交中的本持仓确定性客户端订单 ID 恢复平仓订单归属；仍要求成交数量完整解释交易所数量，不把其他订单成交算入持仓。
5. 无法用成交解释的数量差异超过两分钟后作为对账错误处理并阻止新增风险，后续对账仍可恢复；不再长期把这种差异当成正常运行。
