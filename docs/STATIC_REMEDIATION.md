## 额外稳定性调整

- 关键后台任务异常结束时锁定新增风险，并在提交边界检查任务存活。
- `/api/health` 仅提供匿名存活状态；`/api/readiness` 提供认证后的关键任务存活情况。已有 `/api/ready` 深度检查接口保留。
- 退出服务时收集后台任务异常，避免某个已失败任务阻止后续客户端释放。
- 启动脚本不再匿名请求自动化管理接口；登录后在工作台查看状态。

## 补充复查修复

- 更换或清除 API 凭证时，即使交易所、交易模式和市场类型不变，也必须确认旧账户没有挂单和持仓。检查覆盖未纳入 v2 管理的交易所持仓。
- 自动化关闭后，决策、执行及对账回调不能将状态写成 RUNNING 或 DEGRADED；明确的风险 HALTED 状态保留。后台状态写入在数据库共享锁内比较原始 updated_at，拒绝覆盖并发保存的新配置。
- 登录密钥先在同目录临时文件内设置权限、完整写入并同步，再通过硬链接原子发布；并发生成不会覆盖已存在的正式密钥。生成失败清理临时文件，后续启动可以重试，不会新建空的正式密钥文件。已存在的损坏密钥仍需人工恢复或移除，不自动轮换现有凭证。

本次补充修改通过四个后端文件的 Python AST 解析、Ruff F/B 规则及差异空白检查；未运行测试、构建或服务，也未读取或更改实际密钥。

## 使用变化

服务首次启动会在数据目录创建 `operator-access.key`。后续运行修复将完整路径移至本机启动器输出，登录页仅显示文件名；操作者在本机读取后输入。
Windows 新建密钥文件在写入前移除继承 ACL 并授予当前用户完全控制；其他平台创建权限为 0600。
密钥生成失败会阻止服务启动，不会退回匿名模式。拥有该用户文件访问权限的程序仍属于同一信任边界。

浏览器会话八小时过期；服务重启也会清空会话。脚本可用 Bearer 密钥访问管理接口。
当前仍采用单服务进程，不能直接增加 Uvicorn workers；多进程执行需要另行实现执行所有者与跨进程协调。

更新后的前端需要重新构建，服务需要重新启动才能使用本轮源码。按用户要求，本轮没有执行这些动作。

## 静态验证与边界

执行范围仅限 Python AST 解析、Ruff 名称/缺陷规则、TypeScript noEmit 类型检查及修改过的前端文件 ESLint。
这些检查不执行应用业务，不能替代成交、断网、重启和浏览器交互验证。

本轮没有重写整个 API 单体，也没有把所有同步数据库访问移出事件循环；行情采集与 LLM 的进一步解耦、完整 Live 管理、多进程支持和保证金冻结口径仍属后续架构工作。图表启用指标仍按有界窗口计算，已减少未启用计算与全量图表数据提交，未声称实现所有指标的增量算法。
