# COSMOS Quant

COSMOS Quant 是面向个人运行、以 **OKX USDT 永续合约**为主路径的可解释加密货币量化交易系统。策略、回测、风险审核与执行使用同一份 `StrategyPlan`：方向、开仓区间、杠杆、保证金模式、止盈、止损、仓位、失效条件和生成依据都能直接阅读，也能被执行引擎无歧义消费。现货路径保留为兼容模式。

- TradingView Lightweight Charts 专业 K 线工作台；支持缩放、平移、十字光标、成交量、EMA/SMA、布林带、VWAP、RSI、MACD，以及趋势线、水平线、垂直线、矩形与斐波那契绘图
- 关注列表品种切换、策略价位叠加、真实持仓/敞口/未实现盈亏、订单成交进度与受控人工撤单
- 趋势回踩、均值回归、区间突破三类确定性策略；市场状态采用三家评分和可执行信号竞争，不确定时保持 `FLAT`
- 非空公开策略库：98 个单腿可执行模板、50 个单腿原型、6 个配对研究模板和 2 个期现 Carry 模板；Agent 的统一检索入口可读取全部 106 个公开先验，并明确区分认证后可执行与研究专用规格；均带版本、出处、适用市场状态、数据要求和受约束规格

## 安装与启动

需要 Python 3.12+ 与 Node.js 20+：

```powershell
Copy-Item .env.example .env
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
npm install
npm start
```

打开 <http://127.0.0.1:8000>。`npm start` 会先构建前端，再由 FastAPI 在同一端口托管网站。开发模式可使用 `npm run dev`。

长期运行建议使用项目内的受管启动器。首次启动会构建前端并等待健康检查通过；后续启动不会重复构建：

```powershell
npm run service:start:build
npm run service:status
npm run service:stop
```

启动器会拒绝重复进程，记录受管 PID，将标准输出与错误写入 `output/`，并在 30 秒内无法通过 `/api/health` 时返回失败。应用重启时会把被进程中断的 Agent 工具调用收口为终态；如果中断调用可能已经影响订单或仓位，系统会进入全局停机并要求先对账，不会盲目重试。项目内启动器不等于操作系统开机自启；无人值守实盘机器还应由操作者在完成测试网前向验收后配置 Windows 服务或任务计划。

## 你需要填写什么

全部在网站“系统设置”中填写，不需要把密钥发给开发者：

1. 交易所：合约交易使用 OKX；Binance 永续目前只读。
2. 模式：先测试网，再实盘。
3. 市场选择 USDT 永续，并配置全仓/逐仓、执行杠杆、交易品种和周期。模拟本金只用于纸面账户。
4. 如果本机不能直连交易所，填写本地 HTTP(S) 代理地址，例如 `http://127.0.0.1:7890`。
5. API Key、Secret；OKX 还需要 Passphrase。
6. 风险上限、策略扫描间隔，以及是否允许自动执行。
7. 实盘时打开真实交易开关并输入 `I ACCEPT LIVE TRADING RISK`。

API Key 只授予读取与交易权限，**禁止提现权限**，并在交易所绑定本机出口 IP。运行机器必须能解析并访问所选交易所域名。

测试网与实盘必须分别填写各自的 API Key。系统不会把测试网凭证复用到实盘，也不会在切换环境时带入密码框。旧环境仍有挂单或持仓时，设置切换会 fail closed。

## 推荐启用顺序

1. 纸面模式选择 USDT 永续，确认多空策略、保证金占用、回测、审核、自动执行和停机流程。
2. 配置测试网 API，点击“测试连接”，必须同时通过公共行情、私有账户和原子保护单检查。
   OKX Demo 账户首次使用合约时，需要先在网页或 App 将 Account mode 设为 Futures mode；首次设置不能由 API 代办。
3. 点击“开始保护单验收”：系统会在测试网提交一个远离市价的最小订单，查询确认交易所原生止盈止损，再立即撤销；通过前禁止交易所自动执行。
4. 在测试网连续运行并演练断网、重启、部分成交、撤单和紧急停机。OKX 永续必须使用 `net_mode` 单向持仓模式；反向开仓前必须先平掉原方向。
5. 实盘从很小的风险额度开始；建议单笔风险不超过权益的 0.25%–0.5%。

## AI 服务配置

左侧导航的“AI 服务”页面用于配置 OpenAI、Anthropic、Google Gemini、xAI、DeepSeek、Mistral、Alibaba Qwen 和自定义 OpenAI-compatible 端点：

1. 选择厂商；系统已填入当前官方端点和稳定模型基线，也允许按你的账户权限修改模型 ID。
2. 点击“前往官方控制台获取 Key”，在厂商网站创建 API Key。
3. 将 Key 粘贴到密码框。Key 只写入本机操作系统凭证库，接口只返回“已配置/未配置”，不会回显原值。
4. 点击“保存 AI 配置”，再点击“测试连接”；系统会验证鉴权、模型目录和最小结构化输出，并显示延迟与当前模型可用性。
5. 验收通过后，如需参与自动研究路由，再打开“加入路由”并设置故障切换或双模型复核。建议逐家验收，不要一次启用未经测试的厂商。

直接地址为 `http://127.0.0.1:8000/?section=ai`。如果 8000 端口被其他本机服务占用，可换用其他端口启动 API。策略生成中心的“生成 AI 研究候选”只登记 `proposed` 候选；AI 结果不能直接激活策略或执行交易。

## 交易 Agent

左侧“交易 Agent”页面用于建立长期目标和最小权限授权。AI 在这里承担的是受约束的编排与推理，而不是直接输出任意交易所请求：它只能从注册工具中选择动作，所有参数先经过非 LLM 权限门，再进入既有回测、风险、执行和对账模块。

推荐顺序：

1. 先创建 `research` 授权并观察运行记录，确认模型在证据不足时选择 `WAIT`。
2. 切换到 Paper 环境，创建 `paper` 授权；将单笔风险、日内回撤、每日交易和持仓上限设得低于平台硬上限。
3. 完成多次“事件 → 分析 → 计划 → 回测 → 授权 → 保护下单 → 监控 → 平仓复盘”闭环，并在页面的 `SANDBOX FORWARD EVIDENCE` 中积累至少 30 个完整回合、20 个独立 Agent 执行批次和为正的近期 R 期望；观察天数只作诊断，不再是盈利或实盘评审硬门槛。
4. 先后通过交易所测试网的原子保护单 commissioning 与 Agent 仓位管理 commissioning，再创建 `sandbox` 授权。
5. `live_capped` 只有在平台已显式解锁实盘时才能保存；策略仍绑定权限指纹，授权变化后旧计划自动失效。
6. 当前向报告达到门槛后，在设置页切换到实盘、填写独立实盘 API、通过连接测试并输入实盘确认短语。系统可在同一次保存中暂停全部活动 sandbox 交易目标，并把操作者选定的目标原子升级为不增加风险额度的 `live_capped` 目标；研究目标保留。存在未平仓、待复盘或不确定回合时迁移会被拒绝。

Paper 已支持 Agent 主动减仓/清仓并同步调整模拟保护数量。OKX 永续已实现“reduce-only 成交 → 附加 Algo 保护单缩量/撤销 → 最终状态回查 → 仓位数量复核”的安全流程；只接受最终查询结果，不把 API 接收回执当作成功。交易所 Agent 开仓、主动减仓和清仓必须另行通过设置页的 OKX Demo 仓位管理验收，未通过时保持硬锁定；失败或结果不确定会进入 `UNCERTAIN` 并触发全局停机。

交易 Agent 页会显示统一的自主交易就绪清单。也可直接调用 `GET /api/agent/readiness`，检查 AI、执行网关、仓位管理、风险闸、权限、目标与待对账回合；所有检查通过才代表当前环境具备自主交易运行条件。

`GET /api/agent/performance?autonomy_mode=sandbox` 返回测试网前向验收报告。报告排除账户其他交易、未平仓浮盈和无法确定性归因的回合；完整回合、独立执行批次、PF、R 期望、近期表现、回撤和连续亏损阈值可在设置页调整，观察跨度只显示为诊断信息。报告通过仍不等于保证未来盈利。

同一市场出现多个可执行策略时，Agent 会先让候选使用相同数据、费用、滑点、历史资金费和因果持仓量完成 Walk-forward。页面同时展示完整样本、最新 25% 窗口、成本压力、回撤、胜率和交易数，并给出透明的 0–100 证据排序分：历史证据占 70%，当前确定性信号占 20%，市场状态适配占 10%。该分数只用于在已通过硬门槛的候选之间排序，不是预测胜率，也不会成为额外的机械开仓限制。

运行证据链中的每个候选都可在交易 Agent 页面直接展开完整回测：权益曲线、成本拆分、最近窗口、逐笔成交、稳健性门槛和数据指纹使用同一份持久化产物，也可用最新已收盘行情重新运行。计划级回测严格绑定当前计划方向；做空计划不能再用混合了做多交易的双向结果完成审核或 Agent 授权，旧的未标记方向产物会被视为过期并要求重跑。

代码通过自动化测试不等同于交易所账户验收。没有用户自己的测试网 API、已启用的合约账户模式和可达网络，无法替代真实交易所的端到端认证、下单与回报验证。回测包含手续费、滑点与交易所可提供的历史资金费率/持仓量；历史数据不可用或覆盖不足时明确披露，绝不拿当前值回填。实时开仓风控仍使用交易所当前资金费率和最新市场证据。
